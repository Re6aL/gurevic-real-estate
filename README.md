# Gurevic Real Estate — черновик сайта

Статический сайт агентства недвижимости (Будва, Черногория). Без сборки и зависимостей:
открывается любым HTTP-сервером, хостится где угодно (GitHub Pages, Netlify, обычный хостинг).

## Структура

```
index.html      — главная: герой-слайдшоу, фильтры, каталог, комплексы, инвестиции, о нас, форма
object.html     — страница объекта (?id=...): галерея, описание, карточки юнитов, карта
map.html        — КАРТА ОБЪЕКТОВ: Leaflet+OSM, маркеры-ценники, мини-карточки, режим Список
leads.html      — демо-панель: заявки и переписки бота (localStorage этого браузера)
css/style.css   — все стили + @font-face (Futura PT)
js/config.js    — справочники: DICT, LOCATIONS, LOCATION_COORDS (правится вручную)
js/data.js      — БАЗА ОБЪЕКТОВ (LISTINGS) — можно генерировать из Notion
js/main.js      — рендер карточек/комплексов, фильтр (цена/площадь от-до, сортировка), дропдаун, форма
js/object.js    — рендер страницы объекта (юниты-карточки + Google-карта)
js/chat.js      — чат-виджет с ассистентом + запись переписки
tools/notion_sync.py — синхронизация каталога из Notion CRM → js/data.js
assets/fonts/   — Futura PT (woff2) + исходники futura-pt.zip
img/            — logo-mark.png (марка, из настоящего лого), logo-stacked.png, logo-navy.jpg
BG_images/      — фоны страниц (01 герой, 02 инвестиции, 03 контакты) + оригиналы лого
```

Порядок подключения JS важен: `config.js` → `data.js` → `main.js`/`object.js` → `chat.js`.

## Запуск локально / предпросмотр в браузере

Самый простой способ в Windows — дважды кликнуть `start-preview.cmd`.
Откроется браузер с адресом `http://localhost:8768`. Окно запуска нужно
оставить открытым; Enter в этом окне останавливает локальный сервер.

После изменения HTML/CSS/JS достаточно обновить страницу (`Ctrl+R`).

Ручной запуск:

```
py -3 -m http.server 8768
```

затем открыть в Chrome: http://localhost:8768
Можно также просто дважды кликнуть `index.html` (откроется через file://), но сервер надёжнее.

## Публикация черновика на GitHub Pages

Сайт уже подходит для GitHub Pages: сборка не нужна, а ссылки на CSS, JS,
изображения, карту и страницы объектов используют относительные пути.

1. Создать на GitHub репозиторий, например `gurevic-real-estate`.
2. Подключить его как `origin` и отправить ветку сайта.
3. В репозитории открыть **Settings → Pages**.
4. В **Build and deployment** выбрать **Deploy from a branch**.
5. Выбрать основную ветку и каталог **/(root)**.

Адрес будет иметь вид:
`https://<имя-пользователя>.github.io/gurevic-real-estate/`.
После каждого `push` новая версия обычно публикуется через несколько минут.

На бесплатном GitHub Pages репозиторий и сам черновик будут публичными.
В репозитории сайта нельзя хранить Notion-токен, `.env`, ключи или приватные
поля CRM.

### Как изменения из Notion попадают на опубликованный сайт

GitHub Pages не обращается к Notion напрямую. В репозитории подготовлен
workflow `.github/workflows/notion-sync.yml`: он запускается вручную или раз
в час, обновляет только публичные данные и создаёт commit, после которого
GitHub Pages публикует сайт.

Перед первым запуском в **Settings → Secrets and variables → Actions** нужно
создать два **Repository secrets**:

- `NOTION_TOKEN` — read-only token отдельной Notion Integration;
- `NOTION_DB_ID` — ID базы объектов.

Пока в карточках используются нейтральные иллюстрации по типу объекта. Когда
появится общее фотохранилище, фотографии лучше синхронизировать из папок вида
`listings/<Object ID>/` отдельным workflow: сайт будет получать только готовые
публичные URL, а ключ доступа к хранилищу останется в GitHub Secrets.

### Фотографии из Dropbox

Workflow уже поддерживает структуру Dropbox `/<папка>/<Object ID>/`.
Например: `/Website photos/BD-26-019S/00-cover.jpg`. Изображения не должны
превышать 15 MB; первые восемь файлов в естественном порядке имени попадут на
сайт. `00-cover.jpg` станет обложкой.

В GitHub откройте **Settings → Secrets and variables → Actions** и добавьте:

- Secrets: `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_REFRESH_TOKEN`;
- Variable: `DROPBOX_MEDIA_ROOT` — путь к корневой папке, например
  `/Website photos`.

Для Dropbox App требуются только scopes `files.metadata.read` и
`files.content.read`. Используйте refresh token, а не постоянный access token.
После настройки запустите **Actions → Sync public listings from Notion → Run workflow**.

До настройки Secrets workflow корректно пропускает запуск и не пытается
подключаться к Notion.

Режим `py -3 tools/notion_sync.py --watch 300` обновляет локальный
`js/data.js` каждые пять минут, но для появления изменений на GitHub Pages
всё равно нужен commit и push.

Подробные правила по токенам, доступам и действиям при возможной утечке — в
`SECURITY.md`.

- Map Link (goo.gl) разрешается в координаты (кэш в ~/.config/gurevic/maplink_cache.json);
- пустые разделы (например «Комплексы», пока их нет в CRM) скрываются автоматически.
Демо-версия каталога — в git-истории (первый коммит).

## Заявки и переписка бота — как это видеть

Открой `leads.html` — там список заявок и полные диалоги бота с клиентом.
**ВАЖНО:** сейчас данные лежат в `localStorage` браузера посетителя, то есть агентство
их пока НЕ видит централизованно. Чтобы риелтор видел заявки со всех устройств, нужен бэкенд:
объект `record` (данные + `transcript`) из `deliverLead()` в `js/chat.js` надо отправлять
POST-ом на сервер или в Telegram-бота. Точка вставки помечена в коде (`fetch('/api/lead', ...)`).

## Чат-ассистент: план по ИИ

Сейчас — скриптованная анкета (цель→тип→бюджет→район→контакт). Для настоящего ИИ нужен
бэкенд-прокси к Claude API (ключ нельзя держать во фронте): endpoint `/api/chat`,
system-промпт с базой объектов, история диалога. Свободные вопросы вне анкеты уже
роутятся в отдельную ветку — туда и подключается LLM.

## Интеграция с Notion CRM риелтора (каталог объектов из таблицы)

Цель: карточки объектов брать не из `js/data.js`, а из Notion-базы риелтора.
Notion отдаёт данные только через официальный API (публичный URL страницы читать нельзя),
поэтому нужен один из вариантов:

1. **Build-скрипт (проще, дешевле, рекомендуется для начала).**
   Небольшой скрипт (Python/Node) с Notion API-ключом (Integration Token) раз в N минут или
   по кнопке тянет базу `databases.query`, маппит поля в формат `LISTINGS` и переписывает
   `js/data.js` (или `data.json`). Сайт остаётся статикой. Минус — данные обновляются не мгновенно.

2. **Бэкенд-прокси (динамика).**
   Мини-сервер отдаёт `/api/listings`, внутри дергает Notion API и кэширует. Фронт грузит
   каталог через `fetch`. Данные всегда свежие, но нужен хостинг с сервером.

**Скрипт `tools/notion_sync.py`** (stdlib, без pip) — тянет базу и переписывает `js/data.js`.

Токен НЕ хранить в папке сайта (её отдаёт веб-сервер). Кладём вне веб-корня:
`%USERPROFILE%\.config\gurevic\notion.env`
```
NOTION_TOKEN=ntn_xxx
NOTION_DB_ID=<32-символьный id базы>
```
Запуск:
```
python tools/notion_sync.py --dry-run   # предпросмотр (ничего не пишет)
python tools/notion_sync.py             # разовая синхронизация → js/data.js
python tools/notion_sync.py --watch 300 # ПОСТОЯННОЕ обновление каждые 5 мин
```
`--watch` — это и есть «сайт сам обновляется из Notion»: скрипт крутится и каждые N секунд
переписывает каталог; риелтор правит Notion → в пределах интервала сайт обновляется.
Перед первым запуском настроить `FIELD_MAP` в шапке скрипта под названия колонок базы.

Что нужно от риелтора (владельца базы):
- создать **Notion Integration** и получить токен (notion.so/my-integrations);
- в базе **••• → Connections → добавить эту интеграцию** (обычного доступа на почту НЕ хватает —
  API видит только базы, куда явно подключена интеграция);
- прислать **Database ID** (из URL базы) и названия колонок.

Примечание: доступ, который риелтор дал на почту, работает для просмотра человеком в Notion,
но не даёт программного доступа — для интеграции нужен именно Integration Token + подключение
интеграции к базе. Скрипт универсален — Notion-часть переиспользуется в других проектах.
